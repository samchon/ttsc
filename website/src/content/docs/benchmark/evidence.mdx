# Evidence Graph

One coding engine builds the same application twice from the same frozen requirements: once with [`@ttsc/evidence`](/docs/evidence) in the workspace, once with neither. Same template, same instruction sequence, same model and effort. The variable is the graph.

Four subjects in ascending size. Every figure comes from `benchmarks/evidence/aggregate` and from nowhere else.

This cohort was run in [`samchon/lint-plugin-evidence`](https://github.com/samchon/lint-plugin-evidence), the repository `benchmarks/evidence` is vendored from, at revisions `cdbda421` and `0f465f52`, the two `benchmarkRevision` values its cells carry, neither of which is a commit of this repository. Its template, instructions, and toolchain have moved since, so the commands below reproduce the procedure rather than the numbers, and a later cohort measured here is not comparable with this one.

## Coverage

<TtscWebsiteBenchmarkEvidenceCoverage />

Thirteen edges, folded from the leaves up. Serial hops multiply, branches average, and every edge enters once. $C_{a \to b}$ is the share of $a$ that reaches $b$, and $Q_x$ is how whole an $x$ is below itself.

$$
\begin{aligned}
Q_{\text{test}} &= Q_{\text{journey}} = Q_{\text{property}} = 1 \\[2pt]
Q_{\text{dto}} &= C_{\text{column} \to \text{property}} \\[2pt]
Q_{\text{screen}} &= C_{\text{screen} \to \text{journey}} \\[2pt]
Q_{\text{hook}} &= C_{\text{hook} \to \text{screen}} \cdot Q_{\text{screen}} \\[2pt]
Q_{\text{op}} &= \tfrac{1}{2}\left( C_{\text{accessor} \to \text{test}} \cdot Q_{\text{test}} + C_{\text{accessor} \to \text{hook}} \cdot Q_{\text{hook}} \right) \\[2pt]
Q_{\text{model}} &= \tfrac{1}{2}\left( C_{\text{model} \to \text{op}} \cdot Q_{\text{op}} + C_{\text{model} \to \text{dto}} \cdot Q_{\text{dto}} \right)
\end{aligned}
$$

A requirement carries six obligations, and each is worth its own rate times the wholeness of what it reaches.

$$
\text{score} = \frac{1}{6} \left(
\begin{aligned}
& C_{\text{req} \to \text{model}} \cdot Q_{\text{model}} + C_{\text{req} \to \text{op}} \cdot Q_{\text{op}} + C_{\text{req} \to \text{dto}} \cdot Q_{\text{dto}} \\
& {} + C_{\text{req} \to \text{test}} + C_{\text{req} \to \text{screen}} \cdot Q_{\text{screen}} + C_{\text{req} \to \text{journey}}
\end{aligned}
\right)
$$

Averaging the thirteen rates instead scored one subject 58.4% while 76 of its 557 published accessors had an asserting test. Multiplying them scored the same subject 0.003%. [#1088](https://github.com/samchon/ttsc/issues/1088) derives the operators.

## Reproduce

Clone the repository and tell Claude Code to run the benchmark following the benchmark skill. That skill is the procedure this cohort was produced under, and it owns setup, launch, supervision, recovery, and publication. It produces a new cohort rather than this one. Every cell records the revision its launcher read, and a cohort collected after this one also records the repository it was collected from; the aggregate served here predates that field, which is why the attribution above is written out.

```bash
git clone https://github.com/samchon/ttsc.git
cd ttsc
corepack enable
pnpm install
claude "run the evidence benchmark following .agents/skills/benchmark/evidence"
```

The commands it drives, if you would rather drive them yourself:

```bash
pnpm --filter @ttsc/benchmark-evidence start codex <subject> <evidence|plain> <model> <effort>
pnpm --filter @ttsc/benchmark-evidence audit-suspensions
pnpm --filter @ttsc/benchmark-evidence report
pnpm --filter @ttsc/benchmark-evidence charts
```

`<subject>` is a directory under `benchmarks/evidence/requirements`. The runner refuses to launch while anything is uncommitted and records the repository `HEAD` as the run's benchmark revision. `report` writes the aggregate under `benchmarks/evidence/aggregate` and its charts under `website/public/benchmark/evidence`; `charts` redraws those from the published aggregate alone, with no run records present.

`report` refuses to publish over a `coverage.json` it cannot attribute to the cohort being written, so an operator republishing here recounts that file against their own runs or removes it first. `benchmarks/evidence/README.md` documents the runner, the arms, and what a run retains.
