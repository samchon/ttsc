# Evidence Graph

Every specification becomes a compile-time obligation.

`@ttsc/evidence` is a rule contributor to [`@ttsc/lint`](/docs/lint), so it runs inside the type-check you already run. You declare in `lint.config.ts` which artifacts owe answers to which specification units, and a unit nothing answers for is reported as a compile error beside your type errors.

## The failure nobody can see

A type error is caught by the compiler. Wrong behavior is caught by a test. An omission has only ever been caught by a person rereading the specification, the implementation, and the tests until one more round turns up nothing new.

Asking the author does not substitute for that reading. Agents agree to a process and then bypass it, and the agreement is worth nothing as evidence: measured across frontier models, they said yes nearly every time and complied in none of the runs ([2605.01771](https://arxiv.org/abs/2605.01771)). The gap widens with scope. A specification delivered in pieces is answered less faithfully than the same specification delivered at once, and long runs erode the work they already did ([2603.17104](https://arxiv.org/abs/2603.17104), [2603.24755](https://arxiv.org/abs/2603.24755)).

So the working method became the loop: read everything again, fix every finding, restart because one fix broke another, and stop only when a full pass finds nothing. It is the state of the art, and it does work.

It is also where the budget goes. Across the benchmark subjects that loop took most of everything spent, and the delivered work still left requirements unanswered, more of them as the subject grew.

Coverage has no denominator until someone counts the specification. This plugin hands that count to the compiler.

## An obligation is a pair

A **claim** names the artifacts that owe answers. A **reference** names the population they owe answers to. Every claim-reference pair is one independently complete obligation, and an acknowledgement toward one pair never counts toward another.

```ts
// lint.config.ts
{
  type: "typescript",
  files: ["src/components/**/*.tsx"],
  symbol: "function",
  reference: {
    type: "markdown",
    files: ["docs/requirements/**/*.md"],
    symbol: ["h2", "h3"],
  },
}
```

Read as a sentence, that says the components implement the requirements. Every H2 and H3 under `docs/requirements` now owes a citation from some function under `src/components`, and the compiler is what counts them.

A real project stacks those pairs into layers, each one grounded in the layer above it.

## The tag is the answer

```tsx
/**
 * @evidence docs/requirements/discount.md#coupon-stacking States the per-issuer stacking limit this section defines, in the buyer's words.
 * @evidence POST:/orders/{orderId}/coupons Explains the rejection this endpoint returns for an over-stacked coupon set.
 * @evidence {@link hooks.useCouponStacking} Renders the limit this hook resolves.
 * @evidence docs/principles.md#no-hard-coding Renders limits from props instead of branching on known issuer names.
 * @evidenceExclude docs/principles.md#fix-root-causes-not-symptoms No failure to fix.
 */
export function CouponStackingNotice(props: IProps): JSX.Element;
```

`@evidence` states what this declaration answers for and why. `@evidenceExclude` states why nothing here owes the target at all.

The first two targets are the specification this screen implements and the endpoint behind it. The third is the hook it renders. The last two are project principles, which the same machinery turns into an obligation on every function you select, so "no hard coding" stops being advice nobody can audit.

Neither tag is accepted without a reason, and that reason exists for a human reviewer rather than for machine judgment. No rule scores whether the prose is sincere, and [Rules](/docs/evidence/rules) explains why none ever will.

## An unanswered unit fails the build

```bash
$ npx ttsc
error TS16411: [evidence/graph] Missing acknowledgement for 'docs/requirements/discount.md#coupon-stacking'
  (Markdown H2 'Coupon Stacking' at docs/requirements/discount.md:3)
  in Claim 1 reference 1 (markdown, symbols: h2, h3).

...

Found 5 errors.
```

Each unit fails on its own, because a citation of one unit says nothing about another. An agent cannot report the work finished while the build is red, so nothing it skipped stays invisible.

Those diagnostics arrive in the stream that already carries your type errors, in every `ttsc` build, every `--noEmit` check, every `ttsx` run, and in the editor through `ttscserver`. There is no second command to add and no CI job to gate separately.

## Omission is not the only failure

Full coverage counts citations, not truth. A cheap model can write a fluent reason for a section it never opened, and that tag turns the error green while the problem stays. A false tag removes the error, not the problem.

What the citation does buy is that the false claim is now addressed to something. It names the scope it depends on, so a reviewer reads that scope against one sentence instead of hunting a codebase for what might be wrong.

`@evidenceReview` records the verdict, and a fingerprint of the cited content makes it expire when that content moves. Without expiry a review is written once and stays green forever, and on a second pass over a large citation set nobody can tell which verdicts were written against text that has since changed.

That is the division of labor the plugin is built around. The compiler catches omissions. Review catches falsehoods.

## Not only for code

The graph reads no meaning. It reads which units exist, which artifacts owe them, and which citations were written, so it applies wherever a body of work has to honor a body of rules.

Four artifact kinds materialize units: Markdown documents and their headings, Prisma models and their fields, Swagger operations, and TypeScript symbols. A backend graph reaches documents, schema, and code from one configuration, while a graph over documents alone never touches a line of code.

[AutoNovel](https://github.com/samchon/AutoNovel) is the case that makes the point. It writes long-form novels as evidence graphs, where principles and settings are the reviewed source layer and every treatment, script, and manuscript cites the settings it consults and the principles it serves. The compiler has no opinion about prose. It reports that a setting was committed to and that nothing written since ever answered for it.

## Install

```bash
npm install -D ttsc @ttsc/lint @ttsc/evidence typescript
```

`@ttsc/lint` is a peer dependency rather than a bundled one, so the engine you already run is the one that hosts these rules, and there is no `tsconfig.json` plugin entry to add anywhere.

The Prisma and Swagger loaders call a JavaScript bridge, which is why Node.js has to be on the path even though the rules themselves are Go.
