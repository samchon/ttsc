# Validation

`test.yml` runs in-process unit contracts on Linux without building or installing a product CLI. `e2e.yml` owns one Linux job for real processes, source-plugin builds, installation contracts and packed adapter boundaries. `setup.yml` owns the single installation and minimal CLI matrix covering Linux, Windows and macOS on x64 and arm64. Every setup target builds and installs all three native commands and the bundled Go compiler; the smoke runs their version entrypoints, compiles a relative-import project, and executes it through emitted JavaScript and `ttsx`. The other automatic workflows have one job each: build, website and benchmark. With typia, nestia and the installation matrix excluded, the maximum is five jobs. There are no planner or aggregate jobs. Every existing assertion remains in a unit or e2e execution.

Test, e2e, setup, build, website and benchmark jobs target successful completion within ten minutes, including setup and cache actions. They continue past that target so completed runs retain their actual total duration. Stop waiting for a run after ten minutes and continue independent work without cancelling it for elapsed time. A newer commit supersedes and cancels an older validation run on the same branch, so current-head feedback does not queue behind stale work. typia and nestia retain their separate compatibility budgets. Duration acceptance requires successful measured runs.

`node scripts/ci/run-unit-tests.cjs` runs Node function contracts, the transformer and shim AST suites, and the lint, formatting and exit-status corpora through Go functions in one process. The lint corpora use JSON configuration and an in-process parser and checker; they do not require a built launcher, a source-plugin binary or a Node formatter oracle. Twenty-four former evidence consumer scenarios call the actual Go file and graph rules in one process, retaining their inputs, options and diagnostics. Nine file-rule scenarios and both optionless typing controls share one consumer project and one compiler execution. Scoped entries preserve each scenario's rule setting, every typed configuration is compiled, and each negative scenario must contribute its own source-anchored error. Real process and package checks are selected separately, even when their runner is Node or Go. Default local commands still select the complete suite.

Backend benchmark activation uses the prepared consumer workspace and its actual package scripts. Each owning Program starts one watch session, then checks every prescribed activation stage without restarting the compiler. Prisma generation runs again only when an authored schema changes. Claim, requirement-document and installed-accessor assertions remain at every stage. Preparation, initial build and each activation report separate elapsed times; the sessions close their process trees before the workspace can be restored.

`validation-suites.cjs` lists logical suites inside the e2e job. `TTSC_TEST_LAYER=e2e` excludes the units executed by `test.yml`. The lint package's original Go test functions are assigned exactly once: rule, format, fix, contributor, parser and registry behavior runs as Go unit subtests, while command, config-loader, process and linked-file boundaries remain in e2e. The unit batch also runs the complete aggregate behavioral-witness audit after its direct rule assertions. The TypeScript lint fixture-harness cases run as units without building a CLI. Each independent command prints its start, result and elapsed time. `run-validation-group.cjs` merges compiler and lint directory selections into one executor per suite and finishes every independent command, even after a failure. The packed adapter starts in that same bounded batch instead of waiting for all other suites to finish; it owns separate consumer and tarball directories. All suites share one dependency install and one current-platform build. The minimum supported Node release and the current release retain their runtime, project and utility-plugin contracts in that same Linux job and reuse the installed CLI consumer. Windows and macOS install fresh tarballs, compile a relative-import project and execute it through both emitted JavaScript and `ttsx`.

`pnpm test:go` prepares all classified lint fixtures and runs them inside one Go process. Each fixture uses the real config resolver. AST-only rules use the parser and engine; type-aware rules and companion projects load a real compiler program. Expectations, options, filenames, companions and the actual checker are preserved. Empty or unclassified input fails. The production renderer checks every finding's file, rule, severity, line and original order without sorting expectations. A shared command test checks clean, error, warning and warning-with-type-error exit behavior; warning-only corpus fixtures retain their actual command failure assertion. Audited skip fixtures retain their existing Go harnesses. The complete format-project corpus runs through the production format command in that same Go process, preserving config, compiler-program loading, cascades, exact output bytes, status, diagnostic silence and fixture immutability. One formatting launcher scenario retains actual plugin discovery and dispatch. CLI, config, contributor loading and fix boundaries remain integration tests.

Packed adapter and compiler contracts share one dependency-store installation. Each consumer retains its original direct-dependency manifest, so combining the install does not alter automatic plugin discovery. The compiler scenario retains its native TypeScript dependency and every bundled-Go, transform, declaration, source-map and lint-loader assertion; its commands resolve the installed SDK without inheriting the portable suites' system Go override. Next keeps its classic TypeScript dependency. Their source fixtures occupy separate directories. Independent builds use bounded processes. Next builds and matcher probes share one serial phase because they mutate the same configuration and output. The host lifecycle sweep then uses the same worker budget and streams each completed verdict. Bun build and runtime checks finish serially after that sweep: runtime preload writes a source file and the ancestor `bunfig.toml` that other builds must not observe changing. Every phase reports failure without suppressing later phases. Content-keyed plugin binaries survive consumer recreation in the shared test cache.

The custom validation-cache action is removed. The standard Node and Go setup actions retain the pnpm download store, Go modules and Go intermediate objects. No plugin archive, npm archive or foreign SDK archive is uploaded by a custom cache action. Native executables are built from current source. The e2e prerequisite build and ordinary plugin tests share a content-keyed plugin directory within that execution. Tests asserting cold builds, default cache placement, pruning or invalidation retain their isolated roots and environment rules. Installed consumers and their `node_modules` are recreated from current tarballs.

The full build job first builds dependency-independent workspace packages with two bounded processes; VS Code packaging runs after the other packages because it temporarily rewrites its manifest. Each package reports its elapsed time. The CI build builds only the WASM package's TypeScript library, which playground imports; `website.yml` already builds the full WASM binary and now owns the same dist-artifact and packed-tarball assertions formerly repeated by build. The CI build then builds the current Linux platform for its release-candidate graph smoke and Linux ARM, which the installation matrix does not cover. Default `pnpm build` still builds all seven platform packages and full WASM for release. Native platform builds use two bounded processes and a divided Go scheduler budget, reporting each target's elapsed time. The existing official-checksum and embedding checks still run. Every selected native target reaches its verdict; a foreign target's failure does not suppress the graph build when the current-platform compiler succeeded.

`TTSC_TEST_WORKERS` bounds isolated Node processes; each retains serial execution, its own environment and working directory. Identically named files stay together. The parent collects every verdict and owns shared adapter-record cleanup. `TTSC_GO_TEST_WORKERS` bounds independent Go suites; the lint corpus remains one process. The workspace-cache persistence contract runs its four package managers with two bounded processes, each in a separate temporary workspace and home, while each manager retains its cold-build then warm-reuse order. CI passes its shared Go intermediate-object cache through to these managers; the plugin-binary cache being tested remains cold and workspace-local. `TTSC_HOST_WORKERS` bounds packed builds and host contracts inside their existing job.

Run the batch checks with `node --test scripts/ci/validation*.test.cjs scripts/ci/build-scope-union.test.cjs`. Run the full shared batch with `node scripts/ci/run-validation-group.cjs --lanes=all`, or select suites with `--lanes=ttsc-core,ttsc-native`. Debug the lint corpus with `node scripts/test-go-lint.cjs -run=TestLintFixtureCorpus -v`; without arguments it executes the complete engine/config suite.
