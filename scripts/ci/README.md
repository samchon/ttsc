# Validation

The test workflow has one Linux validation job and one installation and minimal CLI matrix covering Linux, Windows and macOS on x64 and arm64. Linux owns portable unit tests, integration boundaries and packed adapter contracts. There are no planner or aggregate jobs. The other automatic workflows have one job each: build, website and benchmark. With typia, nestia and the installation matrix excluded from the requested count, the maximum is four jobs. A removed integration assertion must retain equivalent unit coverage or remain in the batched integration run.

Test, build, website and benchmark jobs target successful completion within ten minutes, including setup and cache actions. They continue past that target so completed runs retain their actual total duration. Stop waiting for a run after ten minutes and continue independent work without cancelling it. Workflow concurrency also preserves running executions when a newer commit arrives; a later execution queues behind the current one. typia and nestia retain their separate compatibility budgets. Duration acceptance requires successful measured runs.

`validation-suites.cjs` lists logical suites inside the Linux job. `run-validation-group.cjs` merges compiler, lint and adapter directory selections into one executor per suite and finishes every independent command, even after a failure. All suites share one dependency install and one current-platform build. The minimum supported Node release and the current release retain their runtime, project and utility-plugin contracts in that same Linux job and reuse the installed CLI consumer. Windows and macOS install fresh tarballs, compile a relative-import project and execute it through both emitted JavaScript and `ttsx`.

`pnpm test:go` prepares all classified lint fixtures and runs them inside one Go process. Each fixture uses the real config resolver. AST-only rules use the parser and engine; type-aware rules and companion projects load a real compiler program. Expectations, options, filenames, companions and the actual checker are preserved. Empty or unclassified input fails. The production renderer checks every finding's file, rule, severity, line and original order without sorting expectations. A shared command test checks clean, error, warning and warning-with-type-error exit behavior; warning-only corpus fixtures retain their actual command failure assertion. Audited skip fixtures retain their existing Go harnesses. The complete format-project corpus runs through the production format command in that same Go process, preserving config, compiler-program loading, cascades, exact output bytes, status, diagnostic silence and fixture immutability. One formatting launcher scenario retains actual plugin discovery and dispatch. CLI, config, contributor loading and fix boundaries remain integration tests.

Packed adapter and compiler contracts share one dependency-store installation. Each consumer retains its original direct-dependency manifest, so combining the install does not alter automatic plugin discovery. The compiler scenario retains its native TypeScript dependency and every bundled-Go, transform, declaration, source-map and lint-loader assertion; its commands resolve the installed SDK without inheriting the portable suites' system Go override. Next keeps its classic TypeScript dependency. Their source fixtures occupy separate directories. Independent builds use bounded processes. Next builds and matcher probes share one serial phase because they mutate the same configuration and output. The host lifecycle sweep then uses the same worker budget and streams each completed verdict. Bun build and runtime checks finish serially after that sweep: runtime preload writes a source file and the ancestor `bunfig.toml` that other builds must not observe changing. Every phase reports failure without suppressing later phases. Content-keyed plugin binaries survive consumer recreation in the shared test cache.

CI caches the pnpm store, Go modules, Go intermediate objects and content-addressed plugins, separated by OS, architecture and Go version. The shared prerequisite build uses that plugin root too, so graph's typia compilation can reuse its content-keyed binary. Native executables are built from current source. Go objects have one saving owner per namespace. Plugin additions have separate group and revision keys. Tests asserting a cold plugin build or cache lifecycle retain their own plugin directories; sharing Go objects does not turn a cold plugin entry into a hit. Default-cache placement tests clear environment overrides.

The Linux packed contracts also persist npm's registry download cache. Every run recreates its consumers and installs the current local tarballs; installed `node_modules` trees are never archived. The installation matrix retains Go objects and dependency stores without restoring or saving the source-plugin archive, because its compiler and runtime smoke tests do not compile plugins.

The full build job also retains verified foreign Go SDK archives and extractions. The existing official-checksum and embedding checks still run. Native platform packages build with two bounded processes inside that one job, with a divided Go scheduler budget. Every target reaches its verdict; a foreign target's failure does not suppress the graph build when the current-platform compiler succeeded.

`TTSC_TEST_WORKERS` bounds isolated Node processes; each retains serial execution, its own environment and working directory. Identically named files stay together. The parent collects every verdict and owns shared adapter-record cleanup. `TTSC_GO_TEST_WORKERS` bounds independent Go suites; the lint corpus remains one process. `TTSC_HOST_WORKERS` bounds packed builds and host contracts inside their existing job.

Run the batch checks with `node --test scripts/ci/validation*.test.cjs scripts/ci/build-scope-union.test.cjs`. Run the full shared batch with `node scripts/ci/run-validation-group.cjs --lanes=all`, or select suites with `--lanes=ttsc-core,ttsc-native`. Debug the lint corpus with `node scripts/test-go-lint.cjs -run=TestLintFixtureCorpus -v`; without arguments it executes the complete engine/config suite.
