# Validation

The test workflow has one Linux validation job and one OS matrix for Windows and macOS installation and minimal CLI execution. Linux owns portable unit tests, integration boundaries and packed adapter contracts. There are no planner or aggregate jobs. The other automatic workflows have one job each: build, website and benchmark. With typia, nestia and the installation matrix excluded from the requested count, the maximum is four jobs.

Test, build, website and benchmark jobs have a ten-minute deadline including setup and cache actions. A deadline failure remains a failed check; the limit does not prove that coverage completes within budget. typia and nestia retain their separate compatibility budgets. Duration acceptance requires successful measured runs.

`validation-suites.cjs` lists logical suites inside the Linux job. `run-validation-group.cjs` merges compiler, lint and adapter directory selections into one executor per suite and finishes every independent command, even after a failure. All suites share one dependency install and one current-platform build. The installed CLI consumer is reused for the minimum supported Node release and the current release. Windows and macOS install fresh tarballs, compile a relative-import project and execute it through both emitted JavaScript and `ttsx`.

`pnpm test:go` prepares all classified lint fixtures and runs them inside one Go process. AST-only rules use the parser and engine; type-aware rules and companion projects load a real compiler program. Expectations, options, filenames, companions and the actual checker are preserved. Empty or unclassified input fails. Every finding's file, rule, severity and line is checked. Audited skip fixtures retain their existing Go harnesses. CLI, config, contributor loading, fix and formatting boundaries remain integration tests.

Packed adapter contracts install one consumer. Independent builds use bounded processes. Next builds and matcher probes share one serial phase because they mutate the same configuration and output. The host lifecycle sweep then uses the same worker budget. Every phase reports failure without suppressing later phases. Content-keyed plugin binaries survive consumer recreation in the shared test cache.

CI caches the pnpm store, Go modules, Go intermediate objects and content-addressed plugins, separated by OS, architecture and Go version. Native executables are built from current source. Go objects have one saving owner per namespace. Plugin additions have separate group and revision keys. Tests asserting a cold plugin build or cache lifecycle retain their own plugin directories; sharing Go objects does not turn a cold plugin entry into a hit. Default-cache placement tests clear environment overrides.

`TTSC_TEST_WORKERS` bounds isolated Node processes; each retains serial execution, its own environment and working directory. Identically named files stay together. The parent collects every verdict and owns shared adapter-record cleanup. `TTSC_GO_TEST_WORKERS` bounds independent Go suites; the lint corpus remains one process. `TTSC_HOST_WORKERS` bounds packed builds and host contracts inside their existing job.

Run the batch checks with `node --test scripts/ci/validation*.test.cjs scripts/ci/build-scope-union.test.cjs`. Run the full shared batch with `node scripts/ci/run-validation-group.cjs --lanes=all`, or select suites with `--lanes=ttsc-core,ttsc-native`. Debug the lint corpus with `node scripts/test-go-lint.cjs -run=TestLintFixtureCorpus -v`; without arguments it executes the complete engine/config suite.
